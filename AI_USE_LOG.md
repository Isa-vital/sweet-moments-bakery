# AI Use Log

## Tool used

OpenAI Codex and OpenAI built-in image generation.

## Purpose

- Build the five-page HTML/CSS/JavaScript website.
- Create a consistent responsive visual design.
- Draft student-project copy and proposed policies.
- Generate illustrative bakery imagery.
- Check links, prices, disclaimers and JavaScript behavior.
- Add and test a frontend-only cart and simulated checkout without collecting personal information or processing payment.
- Redesign the catalogue and product-detail experience from supplied e-commerce layout references while preserving the Sweet Moments visual identity.

## Main prompt

The group supplied a detailed prompt headed **“SWEET MOMENTS BAKERY — E-COMMERCE CAPSTONE WEBSITE”**. It requested a premium five-page website using only HTML5, CSS3 and minimal vanilla JavaScript, compatible with direct browser opening and GitHub Pages, with all ten coursework products, Task 7 payment instructions, proposed policies, local images, responsive design, accessibility, documentation and testing records.

## Recent prompt and revision log

The following instructions were given to OpenAI Codex on **31 October 2026**. Long instructions are summarised faithfully rather than reproduced word for word.

### 1. Mobile navigation and device responsiveness

**Prompt:** “Fix the nav menu on mobile, ensure mobile responsiveness on different screens of different brands. Consider iPhones too.”

**AI-assisted work:** Reviewed and corrected the mobile navigation, menu overlay, spacing, touch targets and responsive breakpoints. The pages were checked at small Android, standard mobile, iPhone, tablet, laptop and desktop widths.

### 2. Frontend shopping cart and simulated checkout

**Prompt summary:** Add a professional but simulated e-commerce journey using only HTML, CSS and vanilla JavaScript. Customers should be able to add products, change quantities, remove products and see the UGX total. Checkout should show an order summary and allow selection of MTN Mobile Money, Airtel Money, Bank Transfer or Cash on Delivery. Each method must show three steps, clearly labelled SAMPLE details, payment-verification guidance and a proposed refund process. The journey must stop before payment confirmation and must not collect names, telephone numbers, addresses, card details, PINs or OTPs. Preserve the five required HTML pages and keep the project compatible with GitHub Pages.

**AI-assisted work:** Implemented a browser-only cart using product IDs and quantities, automatic UGX totals, quantity controls, removal, an order summary, four sample payment methods, verification/refund guidance and a final safety stopping point. No real gateway, database, order submission or customer-information form was added.

### 3. Product catalogue and product-details redesign

**Prompt summary:** Redesign the existing catalogue and shopping experience using supplied Tech Market Ug screenshots as structural references while retaining Sweet Moments Bakery branding. Add a desktop filter sidebar, mobile filter panel, product search, categories, price range, sorting, a responsive product grid, product-detail modal, quantity selector, Add to Cart and Review Order actions. Do not copy Tech Market branding or add fake discounts, reviews or stock information.

**AI-assisted work:** Reworked the Products page into a professional catalogue with filters and sorting, added an accessible same-page product-detail dialog and connected it to the shared cart. The blush, ivory and chocolate visual identity was retained.

### 4. Catalogue image density

**Prompt:** “The product images shouldn’t be tall; at least 2–3 rows should fit on the page.”

**AI-assisted work:** Reduced and standardised catalogue image heights, tightened product-card spacing and preserved readable product information and controls. Responsive checks confirmed that two to three product rows or row starts are visible depending on viewport height.

### 5. Mobile product-detail image height

**Prompt:** “On the product details it’s still so tall.”

**AI-assisted work:** Added compact responsive heights for product-detail images, using a shorter crop on phones and moderate heights on tablets. The redundant single-image thumbnail was hidden on phones so the product name, price and controls appear sooner.

### 6. Reduce repeated coursework wording

**Prompt summary:** Keep the student-project identification in the header, footer, About page and How to Pay page, but remove repeated school-project/frontend wording from other page content, especially Products.

**AI-assisted work:** Removed repeated coursework and frontend-demonstration messages from the catalogue, product descriptions, product-detail content and cart. The required site-wide disclosure and the detailed payment safety notices were preserved.

### 7. Simplify the product-detail modal

**Prompt:** “Remove these,” referring to the highlighted availability notice and Ordering/Payment information cards in the product-detail modal.

**AI-assisted work:** Removed both highlighted blocks, deleted their unused CSS and reduced the spacing above the quantity and purchase controls.

### 8. Coursework compliance review and final website content

**Prompt summary:** Review Tasks 6 to 10 against the lecturer's original capstone PDF, identify what was already covered and complete the remaining website-side requirements before preparing the hand-in document.

**AI-assisted work:** Confirmed the five required pages and the published GitHub Pages address, added a concise rationale for the proposed payment methods and cryptocurrency decision with a Bank of Uganda source, strengthened the Policies page with honest-claims, impersonation and fake-review guidance, and corrected the five-person testing record to use the lecturer's required price, payment and delivery tasks. Human survey responses, user-testing results, security-account actions and peer records were deliberately left for the group to complete honestly.
